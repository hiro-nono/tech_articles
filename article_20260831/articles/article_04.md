## Docker
### Dockerとは
まず、DockerとはPaaSを提供するクラウドベンダーだったdotCloudが、オープンソースのソフトウェアとして公開しました。そのDockerは当初から注目され、dotCloud社はDockerという社名に変更するくらいに、急成長します。まさに、トレンドの技術といえます。

Dockerは、コンテナを開発者が扱いやすい形で提供し、コンテナ技術の普及に貢献したプラットフォームサービスといえます。

では、なぜ Dockerが広く普及したのでしょうか。それは、コンテナを扱いやすくし、アプリケーションの実行環境を再現可能な形で管理できるようにしたことです。それでは、下記では深堀をおこなっていきます。

### 簡便な構築と運用
コンテナという考え方は、Docker以前より存在していました。まさに、ここまで普及した大きな理由が、*コンテナを扱うための操作をわかりやすくしたこと*です。

コンテナを利用するには、アプリケーションを隔離して実行するだけでなく、その中で動くアプリケーション・必要なファイル・ライブラリを用意する必要があります。これらを毎回手作業で実行していては、環境を再現することが難しくなります。

そこで、Dockerではコンテナの作成・実行・管理のための仕組みを提供することで、コマンドから簡単に扱えるようにしました。

```
# 作成・実行
docker run
```

```
# 停止
docker stop
```

```
# 削除
docker rm
```

のように、複雑な仕組みを直接操作することなく、コンテナを扱うことができます。

### 強固な再現性
Dockerでは、アプリケーションを動作させるための環境を定義し、それを再現するという考え方も重要になります。

環境を、手作業ではなくファイルとして定義できます。これによって、その定義を利用して同じ環境を何度でも作成できるようになります。

## 環境をコードで管理する
ここまで、環境とはアプリケーションを動作させるために必要なものが揃った状態だと説明しました。しかし、これらを人が手作業で用意すると、「Aさんの環境では動くけど、Bさんの環境では動かない」といった環境の差分が生まれると説明してきました。

Dockerでは、環境を作るための手順をファイルに記述するという考え方をとります。

このファイルが、Dockerfileです。

### Dockerfile

Dockerfileには、

- どのOSを使うか
- どのランタイムを用意するか
- どのライブラリをインストールするか
- どのファイルを配置するか
- どのようなコマンドでアプリケーションを起動するか

といった、コンテナを作るために必要な内容を記述します。いわば、*環境を作るための定義書*です。

### イメージ

では、このDockerfileをそのまま使ってコンテナを動かすのでしょうか。

Dockerでは、Dockerfileをビルドすることで、Dockerイメージというものを作成します。
このイメージには、コンテナを動作させるために必要なファイルやアプリケーションがまとめられています。そして、このイメージをもとに、コンテナを作成して実行します。

イメージは、よく金型に例えられます。なぜならば、このイメージから、複数のコンテナを作成できるためです。実際にDocker Hubでは、一般に公開されています。

### Dockerまとめ

つまり、

- Dockerfile：どのような環境を作るのかを定義するもの
- イメージ：Dockerfileから作られる、コンテナの元になるもの
- コンテナ：イメージをもとに実際に動作しているもの

という関係になります。

この仕組みによって、環境を人の記憶や手作業に頼るのではなく、Dockerfileというコードとして管理できるようになります。

例えば、開発者AがDockerfileからイメージを作り、そのイメージからコンテナを実行したとします。

開発者Bも同じDockerfileからイメージを作れば、同じ定義に基づいた環境を用意できます。

開発者A => Dockerfile => イメージ => コンテナ
                                     
開発者B => Dockerfile => イメージ => コンテナ

さらにDockerfileは、アプリケーションのコードと同じようにGitなどで管理できます。

そのため、環境を作るための手順を人の記憶や手作業に頼るのではなく、コードとして共有・変更・再利用できるようになります。

Dockerで重要になるのは、単にアプリケーションを隔離して動作させることだけではありません。アプリケーションが動作するために必要な環境そのものを定義し、その定義から同じ環境を何度でも作れるようにすることにも大きな意味があります。
