# なぜポインタでnilが設定できるのか
## ポインタとは
### 変数はメモリに保存される
　まず、プログラムで宣言した変数は、実行時にメモリ上に配置されます。その際、データが保存されているメモリ上の場所を識別するための情報がアドレスです。

例えば、次のコードを見てみましょう。

```
func main() {
    value := 42

    // 値を出力
    fmt.Printf("%d\n", value)

    // アドレスを出力
    // `& + 変数`　でアドレスを取得
    fmt.Printf("%p\n", &value)
}
```

実行すると、次のような結果になります。
```
42
0xc0000120d0
```
　ここでは、`value` に `42` が格納されており、その値が配置されているメモリ上のアドレスを `&value` で取得しています

　よく、メモリについての解説で、箱をイメージさせる説明が散見されます。メモリを「箱」に例えると、変数自体はその箱に名前を付けて、箱の中にデータを入れているように考えることができます。

　例えば value という変数に 42 を代入すると、プログラムはその値をメモリ上に保持します。そして、その値を読み取ったり、別の値に書き換えたりすることで、四則演算やデータ処理などを行います。

### ポインタとはアドレスを値として持つもの
　では、先ほどの変数のアドレスを別の変数に保存してみましょう。

```
func main() {
    value := 42

    // アドレスを宣言
    ptr := &value

    // 値を出力
    fmt.Printf("%p\n", ptr)

    // ポインタを出力
    fmt.Printf("%d\n", *ptr)
}
```

結果は次のようになります。
```
0xc0000120d0
42
```

　ここでは、先ほどと同様の変数「42」を宣言し、変数ptrに変数valueのアドレスを入れています。つまり、上から
1. valueのアドレスをptrに代入し、その値を出力
2. ptrのアドレスが持つ値を出力
といった具合です。

　つまり、`ptr` は `value` の値である `42` を直接持っているのではなく、`value` が配置されているメモリ上のアドレスを持っています。

  そして、 `*ptr`とすることで、ptr が持っているアドレスをもとに、そのアドレスに配置されている値を取得できます。


  先ほどの「箱」の例で考えてみましょう。
  `value`　の入っている箱Aがあるとします。その箱Aが置かれる場所 `0xc0000120d0` とします。そして、`ptr` という箱Bを用意します。このとき、箱Bは、箱Aそのものをマトリョーシカのように持っているのではなく、「箱がどこにあるか」という情報を持っています。

  そのため、 `ptr` を見ると、箱Aの場所がわかるため、 `*ptr` とすると、その場所にある箱の中身、つまり、 `42` が取得できます。

　このように、ポインタは別の値が保存されているメモリ上のアドレスを値として保持し、そのアドレスを通じて元の値にアクセスできるものです。

なお、&（アンパサンド） と *（アスタリスク） にはそれぞれ役割があります。

- &value：value のアドレスを取得する
- *ptr：ptr が指しているアドレスの値を取得する

## nilについて
### 何もない

　nilとは、「何も値がないこと」や「存在しないこと」を指す値です。
　
　例えば、文字列型には空文字を表す "" があり、数値型には 0 があります。しかし、これらは「何もない」ことを表しているわけではありません。

```
var name string = ""
var age int = 0
```

　`name` には「長さ0の文字列」が存在し、`age` には「0という数値」が存在しています。

　一方、nil は値そのものを表すものではなく、値が存在しない状態を表します。

- "" → 空の文字列という値が存在する
- 0 → 0という数値が存在する
- nil → 値が存在しない状態

　そのため、次のように string や int に nil を代入することはできません。

```
var name string = nil // エラー
var age int = nil     // エラー
```

　これは、string と int が nil を持つことのできない型だからです。

## 「何も指していない」という状態を表現できるから
　先に、string型やint型はnilを持てないことを確認しました。ただ、ポインタはnilを持つことができます。

```
var name *string = nil
```

　これは「string の値が nil になっている」という意味ではありません。`name`　はstringを指すポインタですが、現在はどのstringもさしていない状態です。

？？？

　つまり、先述の通りに、ポインタは値そのものではなく、値の存在するメモリ上のアドレスを持つわけですから、ポインタは「値を指している状態」だけでなく、「何も指していない状態」も表現できます。これが、ポインタで nil を設定できる理由になります。

# どんな時に使うの？

　ポインタは、主に関数から呼び出し元の値を書き換えたいときなどに使います。

## ポインタを使わない
　ポインタを使わずに値を渡した場合、関数内で値を書き換えても、元の変数には影響しません。

```
func increment(value int) { 
    value += 100 
} 

func main() { 
    value := 42 
    increment(value) 
    fmt.Println(value) // 42 
}
```

　これは、関数に value の値がコピーされて渡されるためです。コピーされているため、関数内ではコピーされた値が更新されるのですが、呼び出し元の `value` は更新されません。

※ ポインタを使わずに値を変更したい場合は、 `increment()` 関数で `return` し、呼び出し元で再代入することで更新できます。
```
func increment(value int) int { 
    return value + 100 
} 

func main() { 
    value := 42 
    value = increment(value) // 再代入
    fmt.Println(value) // 142 
}
```

## ポインタを使う
　一方、ポインタを使うと、元の変数を直接書き換えることができます。

```
func increment(value *int) { 
    *value += 100 
} 

func main() { 
    value := 42 
    increment(&value) // メモリのアドレスを渡す 
    fmt.Println(value) // 142 
}
```

　ポインタを使った場合は、value のアドレスを渡すため、関数内から元の値を変更できます。

　値を `return` して再代入する方法でも、値を書き換えることはできます。それでもポインタを使う理由は、呼び出し元の値を直接変更でき、値を返す必要がないためです。特に、複数の値を変更したい場合や、大きなデータをコピーしたくない場合に、ポインタが役立ちます。

# コラム（& と *）

　Goでは、ポインタを扱う際に、 `&` と `*` を使います。変数の前に、それぞれをつけることで、アドレスの取得やポインタの指す値の取得を行います。
- `&` ：変数のアドレスを取得する
- `*` ：ポインタが指している値を取得する

```
value := 42 
ptr := &value // valueのアドレスを取得 
fmt.Println(*ptr) // ptrが指す値を取得 → 42
```
