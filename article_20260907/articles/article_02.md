## イメージの設計書
### Dockerfile

Dockerでは、アプリケーションの実行環境をイメージとして作成・管理することで、環境構築を手軽にしていることを説明しました。

では、そのイメージはどのように作成されるのでしょうか。

Dockerfileとは、イメージを作成するための手順が書かれたファイルです。Dockerは、Dockerfileに記述された手順に従って、アプリケーションのソースコードなどを含むビルドコンテキストを参照しながら、Dockerイメージを作成します。

次のような手順を記述できます。

- どのイメージを基盤として使用するのか
- アプリケーションのファイルをどこに配置するのか
- ライブラリをどのようにインストールするのか
- どのようにビルドするのか
- コンテナ起動時に何を実行するのか

### 書いてみる

今回は、Go言語でのサンプルを書いてみました。

```
FROM golang:1.26

WORKDIR /app

COPY . .

RUN go build -o server .

CMD ["./server"]
```

上記を1つずつ見ていきます。

1. FROM : Goの実行・ビルド環境を選択
2. WORKDIR : コンテナ内の作業ディレクトリを設定
3. COPY : ローカルのアプリケーションをコピー
4. RUN : Goアプリケーションをビルド
5. CMD : コンテナ起動時にアプリケーションを実行

順を追って説明しています。

まず、FROMでは、基盤となるイメージを指定します。例では、**golang:1.26**としていますから、ここでは「Go言語のバージョン1.26」のイメージを指定していることになります。

次に、WORKDIRでは、コンテナ内のディレクトリを設定します。よくターミナル等で`wkdir sample-app`としてローカル環境にディレクトリを作成しますが、それをコンテナでも行うイメージです。

そして、COPYでは、`COPY <コピー元> <コピー先>`という形式で記述します。ですので、今回の例では、
- コピー元：.
- コピー先：.
という設定になります。「コピー元の`.`」は、ビルドコンテキストのルートですから、あなたの作成したアプリケーションのディレクトリ配下すべてのコードとなります。また、「コピー先の`.`」は、先ほど`WORKDIR /app`で作成したイメージのディレクトリになります。
つまり、COPYでは、ただコピー＆ペーストしているイメージになりますので、`COPY main.go .`としたり、`COPY main.go /app/main.go`とすることで、対象を指定することが可能です。

※Gitと同じように、コピーしたくないものもあります。そのときには、`.gitignore`のように、`.dockerignore`とすることで、防ぐことができます。

ここでようやくイメージを作成するRUNを行います。まず、`RUN`は、イメージ作成（ビルド）する過程でのコマンドです。
RUNで何を実行するかは言語によって異なります。Go言語はコンパイル言語なので、ここではコンパイル（実行可能なバイナリへ変換）するコマンドを記述しています。

例えばPythonでは、`RUN pip install -r requirements.txt`のようにして、ライブラリをインストールするのみで、コンパイルする必要はありません。
1. `go build` : Goプログラムをコンパイル
2. `-o server` : 出力する実行ファイル名をserverに設定
=> `-o`は、output（出力） を指定するオプションになります。そして、`server`は任意の名前で構いません。
3. `.` : 現在のディレクトリをビルド対象に設定
※ DockerfileのRUNは「Dockerイメージを作る途中で実行する命令」で、「Build、Ship、Run」のRunは「完成したイメージからコンテナを実行する段階」ですので、混同に注意が必要です。

最後に、CMDによって、コンテナが起動したら、そのGoプログラムを実行します。`["./server"]`ですが、先ほどの`-o server`で設定した実行ファイル名になります。つまり、RUNで設定した実行ファイル名と合わせる必要があります。

**遊んでみる**

```
my-go-app/
├── cmd/
│   └── server/
│       └── main.go
├── go.mod
└── Dockerfile
```

というディレクトリを想定します。
そして、/cmd/server/main.goを以下のようにします。

```
package main

import (
	"fmt"
)

func main() {
	fmt.Println("コンテナ起動！！")
}
```

今回のDockerfileを以下のようにします。※実行ファイルを変な名前にしてとAIに頼みましたので、*とても面白い名前*になりましたね。🥔

```
FROM golang:1.26

WORKDIR /app

COPY go.mod ./
COPY cmd/ ./cmd/

RUN go build -o strange-potato ./cmd/server

CMD ["./strange-potato"]
```

おさらいですが、goのバージョン1.26を基盤にして、/appというディレクトリをコンテナに作成します。そして、ローカルのソースコードより、go.modを/app/go.modに、cmd/を/app/cmd/へと今回は一つずつコピーしていきます。strange-potatoという実行ファイルにビルドを起こない、コンテナが起動すると、`コンテナ起動！！`とターミナルに表示されます。

### 設計書からコンテナを作成する

全体の流れとしては、

```
Dockerfile
    │
    │ docker build
    ▼
Docker Image
    │
    │ docker run
    ▼
Containerが作成・起動
    │
    ▼
DockerfileのCMDが実行される
```

となります。

まず、Dockerfileを書いた段階では、イメージ・コンテナともに存在しません。続いて、`docker build`を行うと、Dockerfileが読まれ`RUN`までが実行されます。この段階では、イメージが作成されるのみで、コンテナは存在しません。そして、`docker run`を行うと、`CMD`が実行されます。そして、イメージをもとにコンテナが作成され、コンテナが起動します。すると、`CMD`で設定したGoプログラムを実行します。
